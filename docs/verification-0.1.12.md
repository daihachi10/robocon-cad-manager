# 0.1.12 修正・検証記録

## 修正

- UIスレッドを`OleInitialize`で初期化し、`RegisterDragDrop`の失敗を検出する。
- CF_HDROPはHGLOBALハンドルを`DragQueryFileW`へ渡す。ロックしたメモリのアドレスをハンドルとして渡さない。
- ドロップ元がファイルを提供するか、コピーが許可されているかを確認する。
- 空白領域は現在のフォルダー、フォルダー行はそのフォルダーを追加先にする。ファイル行は拒否する。
- フォルダーのドロップ先強調を、離脱・完了時に解除する。ファイル追加の確認やコピーはOLEコールバック完了後に開始する。
- 「ファイルを開く依頼」をSolidWorksでの「文書が開いた確認」と分離する。開く前の通知では開いていると記録しない。
- 開閉イベント、アプリの再アクティブ化、ローカル一覧更新、削除・名前変更・更新実行前に実文書状態を照合する。
- SolidWorks終了後の古いCOM接続を解放し、再起動後は現在のCOMオブジェクトへ接続する。
- COMが応答待ちの場合は「文書なし」と誤認せず、状態不明として更新実行を延期する。
- 閉じた文書のイベント購読を解放し、同じ文書への二重購読を防止する。イベント受信インターフェースの照会にも対応する。
- 重複する閉じる通知による二重ロック解除を防止する。未送信の変更があるロックは保持する。
- 自分のロックが残っていても、閉じている場合は「閉じています」または「送信待ち」と表示する。
- 常時タイマーや定期ネットワーク通信は追加していない。

環境: Windows x64、MSVC 19.51、CMake/NMake、Release、静的CRT。

| 日本語・空白を含むCF_HDROPデータの取得 | 成功 |
| フォルダー行・空白領域への追加、ファイル行への拒否 | 成功 |
| 複数ファイルのバックグラウンドコピーと変更の自動チェック | 成功 |
| ドロップ強調の解除、コピー後の.gitkeep整理 | 成功 |
| 文書が開いた状態・閉じた状態の照合 | 模擬COMで成功 |
| SolidWorks終了後の残存状態解消・再起動後の再接続 | 模擬COMで成功 |

実行したテスト: `IntegrationFixTest`、`FolderBrowserTest`。ユーザー設定・認証情報・CAD作業リポジトリを変更せず、一時リポジトリと非表示ウィンドウで検証した。

実際のSolidWorks 2025での開閉・終了・再起動、エクスプローラーからマウスを使ったドロップは未検証。テスト中にSolidWorksは起動していない。インストーラーはこのPCに実行しない。性能の再計測も実施していない。

## 原因に関する参照

Microsoftの[RegisterDragDropの説明](https://learn.microsoft.com/ja-jp/windows/win32/api/ole2/nf-ole2-registerdragdrop)に従い、ドラッグ＆ドロップの初期化を`CoInitializeEx`から`OleInitialize`へ変更した。
