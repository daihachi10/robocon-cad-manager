# 更新・送信が途中で止まった場合（0.1.21）

## 今回の修正

これまでの更新は早送りで取り込める場合だけに対応していました。自分の保存済み変更と他の人の変更が両方進むと、更新が繰り返し失敗する状態になっていました。また、別のGitツールで取り込み途中の状態になった場合、通常の選択ファイルの保存では完了できませんでした。

0.1.21では次のように動作します。

- 最新状態を取得し、競合しない保存済み変更をエディターなしで取り込みます。通常の早送りも利用します。履歴の書き換えや強制送信はしません。
- 送信が他の人の更新で拒否された場合、最新状態を取り込んで一度だけ再送信します。通信・認証の失敗では自動取り込みしません。
- 取り込み途中の状態を検出し、専用の確認・完了操作へ案内します。
- 同じファイルの競合や未保存変更の上書きが必要な場合は止め、対象と次の操作を表示します。
- バックグラウンド処理で例外が発生しても、ログを残した画面を閉じられるようにします。

## `.git/MERGE_MSG` のVim警告が残っている人

1. CLIで開いているGitやVimの処理を終了してください。未保存のメッセージが必要なら先に保管してください。同じリポジトリを別のツールから同時操作しないでください。
2. アプリを0.1.21へ更新します。
3. **その他 → 中断した取り込みを確認・完了** を選びます。
4. 競合がなければ、画面に出る対象ファイルを確認して完了します。
5. **保存して送信** を押します。

この完了操作は取り込み対象として既に登録された内容をまとめて記録します。一覧のチェックボックスの選択は使いません。登録後に編集した未保存内容や無関係のファイルを自動で追加しません。確認中に登録内容が変わった場合は、確認からやり直します。

アプリはVimを開きません。`.MERGE_MSG.swp` の自動削除も行わないので、以前のメッセージの復旧データを保持します。CLIで直接Gitを使う場合のエディター設定は変更しません。そのためCLIではSwap警告が引き続き出る可能性があります。

## 「競合」と表示された場合

1. 処理画面のログに対象ファイルと手順が出ます。「閉じる」で戻ります。
2. 表示を「すべてのファイル」に切り替えます。
3. 相手と残す内容を相談します。CADでは両者のファイルを別の場所に保管し、採用する内容を作業フォルダーに保存します。テキストは競合箇所を修正します。
4. SolidWorks・エディターで保存して閉じます。
5. 対象のファイルを右クリックし、**このファイルの競合を解決済みにする** を選びます。削除を採用する場合はファイルを削除し、削除された項目で同じ操作をします。
6. 全対象の解決後、**その他 → 中断した取り込みを確認・完了**、続いて **保存して送信** を実行します。

「解決済みにする」は、現在の内容を正しい結果として登録する操作です。自分側・相手側の内容を自動で判定する機能ではありません。非表示の一時ファイルなど一覧に出ない対象は、管理担当者に対象パスを伝えて解決してください。

## 未保存変更があるとき

双方の変更をまとめる必要があり、未保存の変更も残っている場合は、安全のため取り込みを始めません。送信する変更を選んで保存してください。送信対象にしない変更が残る場合は作業フォルダー外へ退避してから更新します。自動で変更を破棄・一時退避することはありません。

送信だけが失敗した場合も、保存済みの変更はこのPCに残ります。通信や認証を直してから「保存して送信」を再実行できます。認証、接続、権限、実際の競合など、原因ごとの対応が必要なエラーまで無条件に成功させることはありません。

## 技術上の根拠

- Gitの子プロセスだけに `GIT_EDITOR=true`、`GIT_MERGE_AUTOEDIT=no` を設定し、取り込みに `--no-edit` を指定します。ユーザーの全体設定や親プロセスの環境は変更しません。
- 取得と取り込みを `fetch origin main` と `merge FETCH_HEAD` に分け、現在のmainと取得先の履歴を確認します。ユーザーの `pull.rebase` 設定に左右されません。
- Gitの公式説明: [取り込みの完了、競合、エディター制御](https://git-scm.com/docs/git-merge)、[Gitの環境変数](https://git-scm.com/docs/git)。
