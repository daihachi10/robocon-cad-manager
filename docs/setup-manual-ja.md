# 高専ロボコン CAD 管理アプリ 初回導入マニュアル

このマニュアルは、GitHubアカウントを持っていない人が、Windows 11にアプリをインストールし、テスト用リポジトリを使える状態にするまでの手順です。

アプリはGitHubのWeb画面を置き換えるものではありません。CADファイルを取得し、SolidWorksで編集し、変更したファイルをGitHubへ送信する操作を分かりやすくまとめるためのアプリです。

## 作業を始める前に

次のものを用意してください。

- Windows 11 x64のPC
- インターネット接続
- 学校のメールアドレス（例：`matsue-ct.ac.jp`）
- 設計班の管理者から知らされたGitHubリポジトリのURL
- CADを保存する十分な空き容量
- SolidWorks（CADを編集する場合）

GitHubのリポジトリが非公開の場合、管理者からそのリポジトリへの書き込み権限をもらう必要があります。アプリをインストールしただけでは、リポジトリへの権限は付きません。

## 1. GitHubアカウントを作成する

1. ブラウザーで [GitHub](https://github.com/) を開き、「Sign up」または「サインアップ」を選びます。
2. 自分専用のメールアドレスを登録します。学校のメールアドレスを登録する場合は、学校の規則を確認してください。
3. GitHubから届いた確認メールを開き、メールアドレスを認証します。
4. 自分だけが分かるパスワードを設定します。パスワードを他の人と共有しないでください。
5. 表示名とユーザー名を決めます。ユーザー名は、後で管理者へ伝えるGitHub IDです。
6. 二段階認証を設定できる場合は設定します。

卒業後に学校メールが停止される可能性があります。学校の規則で許可されている場合は、復旧用の個人メールアドレスも登録してください。

## 2. 設計班のOrganizationへ参加する

管理者へ次の情報を伝えます。

- GitHubユーザー名（GitHub ID）
- GitHubに登録して認証したメールアドレス

管理者から招待が届いたら、GitHubの通知または招待メールを開いて参加を承認します。対象リポジトリがOrganizationではなく個人所有の場合は、管理者にCollaboratorとして追加してもらいます。

次の状態になっていることを確認します。

- 対象リポジトリをブラウザーで開ける
- リポジトリの「Settings」を勝手に変更できない権限になっている
- 変更を送信できる権限がある

権限がない場合は、アプリの設定を何度やり直しても送信できません。管理者に「対象リポジトリ名」と「必要な権限」を確認してください。

## 3. アプリをインストールする

1. 管理者から受け取った `RoboconCadManagerSetup-*.exe` をダブルクリックします。
2. Windows Defender SmartScreenが表示された場合は、配布元とファイル名を管理者に確認してから実行します。
3. 画面の指示に従ってインストールします。管理者権限は通常必要ありません。
4. インストール中にGit for Windowsの取得が行われます。通信を切らずに待ちます。
5. 完了後、スタートメニューの「高専ロボコン CAD 管理 (RoboconCadManager)」を起動します。

Git、Git LFS、Git Credential Managerはアプリのフォルダー内に用意されます。別途コマンドプロンプトでGitを設定する必要はありません。

## 4. アプリの設定を入力する

起動したら「その他」→「設定」を開き、次の項目を入力します。

| 項目 | 入力例 | 説明 |
|---|---|---|
| 表示名 | `2026冬大会` | アプリ内で見分ける名前。自由に決めます。 |
| GitHubリポジトリURL または 所有者/リポジトリ | `https://github.com/daihachi10/mrp-2026-1st-winter-design-test` | 管理者から指定されたURLをそのまま入力します。`所有者/リポジトリ`の形式も入力できます。 |
| 作業フォルダ | `C:\Users\自分の名前\Documents\GitHub\mrp-2026-1st-winter-design-test` | CADを保存する場所です。複製前は存在しない空のフォルダを指定します。 |
| 変更記録に使う氏名 | `山田太郎` | Gitの変更履歴に表示する名前です。 |
| 変更記録に使うメールアドレス | `自分のGitHub登録メール` | Gitの変更履歴に表示するメールです。GitHubに登録したものを推奨します。 |

入力したら「保存」を押します。

この段階では、LFSロック設定のボタンをまだ押さないでください。先にリポジトリを複製します。作業フォルダが存在しない状態でLFS設定を実行すると失敗します。

## 5. リポジトリを複製する

1. 上部の「その他」を開き、「複製」を選びます。
2. 初回だけ、GitHubへのログイン画面がブラウザーに表示されます。
3. 先ほど作成した自分のGitHubアカウントでログインし、Git Credential Managerの許可を承認します。
4. ブラウザーに「認証が完了しました」と表示されたらブラウザーを閉じます。
5. アプリに戻り、複製が終わるまで待ちます。

この認証では、アプリにPAT（個人アクセストークン）を入力しません。Git Credential ManagerがWindowsに認証情報を保存し、次回以降の取得・送信に利用します。パスワードや認証コードをアプリの設定欄へ入力しないでください。

複製先にファイルや別のGitリポジトリがあると失敗します。既存のフォルダを使う場合は、先に管理者へ相談してください。

## 6. LFSロック設定を追加する

SolidWorksの部品、アセンブリ、図面を同時編集から守る場合に行います。STEPやPDFはLFS対象になっても自動ロックの対象にはなりません。

1. 複製が完了したことを確認します。
2. 「その他」→「設定」を開きます。
3. 「LFSロック設定を追加」を押します。
4. `.gitattributes`へ次の種類の設定が追加され、同じ行は重複しません。
   - `.sldprt` / `.SLDPRT`
   - `.sldasm` / `.SLDASM`
   - `.slddrw` / `.SLDDRW`
   - `.step` / `.STEP`（LFSのみ）
5. 「LFSロック設定を追加しました」と表示されたら、一覧を更新します。

`.gitattributes`も共有するファイルです。変更一覧でチェックを付け、「保存して送信」を実行してください。送信が成功するまで、他のメンバーは同じ設定を取得できません。

## 7. 初回接続を確認する

「更新」を押してGitHubから最新状態を取得します。次のことを確認してください。

- CADファイルが一覧に表示される
- ファイル名、状態、最終編集者、容量が表示される
- `~$`で始まるSolidWorksの一時ファイルが表示されない
- ロック状態が確認できる
- `.gitattributes`を送信した場合、変更がなくなっている

ファイルが表示されないときは、設定の作業フォルダが実際の複製先と一致しているか確認してください。

## 8. 普段の操作

### 作業を始める

1. 「更新」を押して最新状態を取得します。
2. SolidWorksで編集するファイルをアプリから開きます。
3. ロック可能なCADファイルは、開くと自分のロックとして表示されます。
4. 「自分が編集中」と表示されていることを確認して編集します。

SolidWorksから直接開いた場合も、アプリが検知してロックを試みます。別の人がロック中の場合は、相手の名前が表示されます。そのファイルを閉じたり上書きしたりせず、設計リーダーへ連絡してください。

### 変更を送信する

1. SolidWorksで保存してファイルを閉じます。
2. 一覧で送信したいファイルにチェックを付けます。新しい変更は通常自動で選択されます。
3. `~$`で始まる一時ファイルは送信対象になりません。
4. 「保存して送信」を押します。
5. 変更内容を入力し、「実行」を押します。
6. GitHubへの送信が成功したことを確認します。

変更済みのCADファイルは、送信が成功するまでロックが保持されます。送信に失敗した場合は、原因を直してからもう一度「保存して送信」を実行してください。

### 他の人の変更を取得する

作業前に「更新」を押します。「更新」はGitHubから取得してから一覧を更新します。通信を伴わず、PC内の一覧だけを更新したいときは「その他」→「一覧だけ更新」を使います。

## 9. よくある問題

### 「GitHubに認証できません」と表示される

ブラウザーでGitHubにログインし直し、Git Credential Managerの許可を承認してください。学校アカウントと個人アカウントを複数使っている場合は、正しいアカウントでログインしているか確認します。

### 「LFSロック設定に失敗しました」と表示される

次を確認してください。

1. 作業フォルダが複製済みである。
2. 作業フォルダに `.git` フォルダがある。
3. アプリを最新版へ更新している。
4. GitHubに接続できる。

設定行がすでに追加済みなら、同じ操作を繰り返しても重複しません。

### 「変更を送信できません」と表示される

リポジトリへの書き込み権限、認証アカウント、ネットワーク接続を確認します。別の人が先に送信していた場合は、先に「更新」を実行してから再送信します。

### 「複製先のフォルダが既に存在します」と表示される

作業フォルダにファイルが残っています。正しいフォルダか確認し、別の空フォルダを設定するか、管理者へ相談してください。確認せずにフォルダを削除しないでください。

### ファイルに鍵が表示されない

ロック状態を取得できていない可能性があります。「ロック状態を更新」を実行し、ネットワークとGitHubの権限を確認してください。鍵が表示されない状態で、他の人が編集中でないとは判断しないでください。

## 10. 困ったときに管理者へ伝える情報

パスワード、認証コード、PATは送らないでください。次の情報だけを伝えます。

- 表示された日本語メッセージ
- 実行した操作（複製、更新、LFS設定、送信など）
- リポジトリ名
- 対象ファイル名
- 発生した日時
- ネットワークが学校内か自宅か

CADファイルそのものをチャットやメールへ添付する前に、管理者の指示を受けてください。

## 初回導入チェックリスト

- [ ] GitHubアカウントを作成した
- [ ] メールアドレスを認証した
- [ ] Organizationまたは対象リポジトリへ招待された
- [ ] 対象リポジトリをブラウザーで開ける
- [ ] アプリをインストールした
- [ ] 設定の5項目を入力して保存した
- [ ] リポジトリを複製した
- [ ] Git Credential ManagerでGitHubにログインした
- [ ] 必要ならLFSロック設定を追加した
- [ ] `.gitattributes`を送信した
- [ ] 「更新」でファイル一覧を取得できた
- [ ] テスト用ファイルを開き、保存、送信できた

このチェックリストがすべて完了すれば、通常のCAD作業を開始できます。
