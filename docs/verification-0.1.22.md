# 0.1.22 Git LFS本体取得の修正検証

## 修正内容

- Gitの通常ファイルとLFSポインタを区別し、ポインタを0 KBのCAD本体として表示しない。
- 複製後、更新後、利用者による「その他 → 大容量ファイルを取得」、および未取得ファイルを開く前に、`git lfs install --local`、`git lfs pull`、`git lfs checkout` を実行する。
- LFS本体取得時だけ、Cloneを高速化するための`GIT_LFS_SKIP_SMUDGE`を子プロセス環境から外す。
- 取得失敗時は処理画面を閉じず、認証・接続・LFS本体不在などの出力を確認できる。

## 実施結果（2026-10-26）

Windows x64、MSVC 14.51、Git 2.56.0.windows.2、Git LFS 3.8.0で検証した。専用のローカルbareリポジトリへ320 KiBの`.SLDPRT`をLFSで送信し、別Cloneで検証した。実際の設計リポジトリ、設定、SolidWorksファイルには触れていない。

| 検証 | 結果 |
|---|---|
| Clone後にLFSポインタではなく320 KiBの実体を取得 | 成功 |
| 実体をGit内のポインタで置換後、「大容量ファイルを取得」で復旧 | 成功 |
| 更新対象のコミットがない状態で、更新によりポインタを復旧 | 成功 |
| ポインタの検出と一覧上の「LFS未取得」表示 | 成功 |
| 0.1.21の送信・競合復旧・未完了マージの回帰試験 | 成功 |
| 氏名・メール、フォルダー表示、自動選択、100–200% DPI、SolidWorks COM模擬、ドラッグ＆ドロップ | 成功 |
| Releaseビルド | 成功 |

未検証: GitHub上の実LFS容量・帯域上限、認証期限切れ、実SolidWorks文書を用いる本体取得。この場合も取得エラーを処理画面へ残す。
