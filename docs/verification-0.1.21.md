# 0.1.21 更新・送信／未完了取り込みの修正検証

## 修正対象

- 早送りできない履歴の分岐で更新・送信を繰り返し失敗する状態。
- CLIのエディター中断などで `MERGE_HEAD` が残ったとき、選択ファイルの保存では取り込みを完了できない状態。
- バックグラウンド例外時に処理画面が「処理中」のままになる状態。

復旧の手順は [merge-recovery-ja.md](merge-recovery-ja.md) を参照。

## ローカル検証（2026-10-25）

Windows x64、MSVC 14.51、CMake NMake Release、Git 2.56.0.windows.2、Git LFS 3.8.0。一時フォルダーに専用のbareリポジトリと2つのCloneを作り、利用者のCADリポジトリや設定を変更せずに検証した。

| 検証 | 結果 |
|---|---|
| Releaseビルド | 成功 |
| エディターを失敗する設定にしても、アプリのGitだけはエディターを開かない | 成功。親プロセスの環境は保持 |
| 2人の別ファイルの変更で送信拒否 → 取得・取り込み・再送信 | 成功。両方の変更を保持し、2親のマージコミットを作成 |
| ユーザーのpull.rebase=true、merge.ff=only設定があっても正常に取り込む | 成功 |
| 早送り更新、双方の保存済み変更の取り込み | 成功 |
| 未保存変更を伴う履歴分岐 | 取り込みを停止。元の内容とHEADを保持 |
| 未完了の取り込みとSwapファイルを配置 | 通常操作を拒否し、専用操作で完了。Swapファイルは内容ごと保持 |
| 確認後に取り込み対象を変更 | 古い確認結果での完了を拒否 |
| 無関係の未保存ファイル | 取り込みの確定に追加せず保持 |
| 同じバイナリCADファイルの競合 | 自動解決せず停止。自分側・相手側のGitデータを保持 |
| 明示的な解決済み登録 → 取り込み完了 → 送信 | 成功 |
| 送信先に接続できない場合 | 保存済みコミットを保持。接続復旧後の送信だけの再試行に成功 |
| 別ツールの履歴操作中 | 更新・送信を拒否 |
| 例外時の処理画面 | 原因ログと閉じるボタンを表示。閉じた後の親画面操作が可能 |
| 氏名・メール設定、追加・記録・送信の進捗 | 既存GitIdentityTestに合格 |
| フォルダー、変更通知、自動選択、100–200% DPIの自動レイアウト検査 | 既存FolderBrowserTestに合格 |
| SolidWorks状態のCOM模擬試験、OLEドラッグ＆ドロップ、コピー | 既存IntegrationFixTestに合格 |
| 配布検証スクリプト（インストールなし） | 成功。CAD書き込み・氏名メール・フォルダー回帰検証 |
| Inno Setupによるインストーラー生成 | 成功 |

## 未検証・制限

- 写真に写っている別メンバーのPCでの実データ復旧は未検証。実際のVimを起動せず、同じ未完了状態を専用リポジトリに作って検証した。
- SolidWorksの実文書編集、GitHub認証切れ、実ネットワーク切断を伴う操作は今回のローカル試験対象外。通信失敗は到達できない送信先で再現した。
- 手動の競合内容選択は利用者の確認が必要。CADの正しさを自動判定しない。
- 自動更新用に、このPCへのインストールは行っていない。インストール試験はGitHub Actions側で実行する。
- 起動時間・アイドルメモリ・CPUは今回は再測定していない。
